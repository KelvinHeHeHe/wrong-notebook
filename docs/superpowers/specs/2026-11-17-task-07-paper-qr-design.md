# 任务 07：纸质试卷二维码与稳定短码设计

> 状态：已批准（用户选择推荐方案）
> 日期：2026-11-17
> 前置：任务 02～06 与 Next.js 安全升级已完成并合入本地主线。

## 1. 意图

家庭使用的主路径是“电脑组卷并打印、学生直接在纸上作答、家长用手机拍照回传”。当前系统已支持打印与回传，但家长仍需在手机上手动找到同一份试卷。本任务为每份试卷增加稳定、可抄录的短码与二维码，让扫码后在登录保护下直接进入该卷的纸质回传页面，并用内容指纹提示“纸面版次是否仍与系统一致”。

## 2. 目标

1. 每份试卷拥有稳定、唯一、易抄录的 8 位 Base58 打印短码。
2. 服务端按可打印内容计算确定性的 12 位十六进制版次指纹，不维护容易漏增的手工计数器。
3. 打印稿与下载的独立 HTML 同时显示二维码、短码和版次。
4. 二维码进入 `/exams/scan/:printCode?v=:printVersion`；未登录时登录后回到原扫码地址。
5. 当前用户只能解析自己的试卷短码；短码只是定位符，不是授权凭据。
6. 版次一致时直接进入既有 `/exams/:id/attempts/new`；不一致时先警告，再由用户确认继续。
7. 新字段进入备份 v14，并兼容 v11～v13 文件以及短码冲突。

## 3. 最小方案

### 3.1 持久化短码

在 `ExamPaper` 增加可空唯一字段 `printCode String? @unique`。字段保持可空，使既有 SQLite 能通过单条增量迁移安全升级；新建、导入和恢复的试卷均分配短码，既有试卷在首次读取详情或打印身份时惰性补齐。

短码使用去除 `0/O/I/l` 的 Base58 字符表，长度为 8。生成逻辑放在考试打印身份模块，不改变现有错题 6 位 `shortId` 契约。唯一性由数据库索引兜底，冲突时有限重试；并发惰性补齐时读取最终数据库值。

### 3.2 内容版次

版次由服务端对规范化后的可打印内容做 SHA-256，向界面暴露前 12 位十六进制。输入包括试卷标题、分组设置，以及每题的顺序、状态、题干、答案、解析、题型、分值、配图、配图比例/位置和单题留白等会改变纸面或批改语义的字段。

作答、成绩、掌握度、更新时间不进入指纹。打印界面的“是否附答案”和临时全局留白选项也不进入，因为它们不修改试卷本体；二维码标识的是题目内容版次，而不是打印机分页参数。

### 3.3 扫码安全与登录回跳

解析 API 使用 `withUser`，查询条件同时包含 `printCode` 与当前 `userId`。不存在、格式错误和不属于当前用户统一返回未找到，避免泄露其他账号是否存在该短码。

页面仍由现有代理保护。登录页读取 `callbackUrl`，只接受以 `/` 开头且不以 `//` 开头的站内相对地址；成功登录后回到该地址，否则回首页，避免开放重定向。

### 3.4 打印地址与二维码

打印页增加“手机访问地址”输入框，默认取浏览器当前 origin，并在本机保存。二维码值由该地址、短码和版次组成。若地址是 `localhost`、`127.0.0.1` 或 `[::1]`，界面提示手机通常无法访问，应改为 Mac 的局域网地址；短码始终可见，作为二维码不可用时的人工核对信息。

打印身份块放在试卷标题附近，并随页面克隆进入独立 HTML。采用 `qrcode.react` 生成内联 SVG，保证浏览器打印与 HTML 下载无需外部图片服务。

### 3.5 版次不一致

扫码页调用解析 API，并比较二维码携带版次与当前指纹：

- 一致：自动替换到既有回传页面；
- 不一致或二维码未带版次：展示旧版纸张警告、当前试卷标题/短码，并提供“仍然上传”按钮；
- 未找到：显示通用错误和返回试卷列表入口。

系统不阻止旧纸回传，因为家庭场景中家长可能确实要补录旧卷；风险必须显式呈现，不能静默绑定。

## 4. 明确不做

- 不重写浏览器分页引擎，不为每张物理打印页生成独立页码二维码。当前 CSS 分页取决于字体、纸张和打印机，强行承诺页级身份会产生错误关联。
- 不新增 Python OCR 服务、外部短链服务、云端二维码服务或第二套认证。
- 不把手机访问地址持久化到数据库或备份；它只保存在当前浏览器。
- 不自动发现或承诺 Mac 局域网 IP；多网卡、VPN 和防火墙条件下应由用户确认实际地址。

## 5. 数据与备份

- 正式增量迁移新增 `ExamPaper.printCode` 唯一索引，不删除或重建现有数据。
- `BACKUP_VERSION` 从 13 升至 14，`BackupExamPaper` 增加可空 `printCode`。
- v11～v13 缺少字段时生成新短码；v14 恢复时优先保留合法短码，若与目标账号现有数据冲突则生成新码。
- 导出、导入、格式校验与真实 SQLite 往返测试同步更新。

## 6. 测试与验收

1. 单元测试覆盖短码格式/冲突重试、指纹稳定性与内容变化、打印地址规范化、登录回跳安全校验。
2. 集成测试覆盖所有权隔离、版次一致/不一致、惰性补码、v13→v14 和 v14 往返/冲突恢复。
3. 打印组件测试确认二维码 SVG、短码和版次进入打印稿及下载 HTML。
4. Playwright 覆盖扫码精确跳转、旧版警告、未登录回跳和移动端可用性。
5. 正式迁移测试覆盖全新库、既有库升级、唯一索引与重复部署幂等。
6. lint、单元、集成、全量 Vitest、定向 E2E 和完整 CI 通过；锁文件不含 `npmmirror`。

## 7. 已知限制

- 手机要直接打开二维码，Mac 服务必须监听局域网且手机能访问填写的地址；防火墙和访客 Wi-Fi 隔离不由应用自动解决。
- 首批只提供试卷级身份。照片页序和题目匹配继续复用现有回传流程。
- 短码不提供匿名访问；家庭账号仍需登录，这是本地数据和儿童作答数据的安全边界。
