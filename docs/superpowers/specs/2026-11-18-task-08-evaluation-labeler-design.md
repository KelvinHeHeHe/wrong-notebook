# 任务 08：家庭样本评测标注器设计

## 背景与目标

项目已经具备 `scripts/evaluate-exam-answer-extraction.mjs`、人工 manifest 协议和聚合准确率报告，但人工直接编辑 JSON 与归一化区域框成本高，难以稳定建立覆盖小学 1～6 年级、数学/语文/英语和不同题型的真实家庭样本集。

本任务新增一个只在本机使用的可视化标注器。家长或维护者把已脱敏照片放入仓库外的私有目录，在浏览器里填写分层元数据、候选题和学生实际书写答案，并直接在照片上框选答案区域。工具保存可恢复草稿，显式校验通过后才生成现有评测 CLI 可消费的 `manifest.json`。

成功标准是：无需手写坐标即可建立至少 60 道代表性客观题的私有评测集，并得到按年级、学科、题型、书写质量和拍摄质量分层的脱敏报告；不把照片、学生答案、凭据或绝对路径写入仓库、业务数据库或报告。

## 范围

### 包含

- 仓库外私有目录中的 JPEG、PNG、WebP 样本发现与标注。
- 题目候选、学生实际书写答案和每题 1～4 个归一化区域框。
- 年级（1～6）、学科（数学/语文/英语）、题型、书写质量与拍摄质量元数据。
- 自动保存的私有草稿、冲突检测、严格校验和显式导出 manifest。
- 复用现有 AI Provider 与答案提取评测 CLI；报告增加固定枚举维度的分层汇总。
- 合成样本自动化测试和仓库外临时目录端到端验证。

### 不包含

- 收集、提交或生成真实儿童照片。
- 在生产 Next.js 应用中增加页面、API、数据库表或备份字段。
- AI 自动预标注、判分评测、OCR 微服务或 Python 服务。
- 自动裁剪姓名、学校、学号；使用者必须在放入样本目录前完成脱敏。
- 将真实样本或真实 Provider 调用加入 CI。

## 方案比较

### 方案 A：独立的本机回环标注器（采用）

Node.js 脚本固定监听 `127.0.0.1`，浏览器界面通过同源 API 读取私有目录中的图片、保存草稿并导出 manifest。它不进入生产包路径，不访问 SQLite，也不读取应用账号或 AI 密钥。

优点是隐私边界清晰、可视化框选准确、无需新增运行时依赖，并能直接复用现有评测协议。代价是维护一小套仅供开发者/家庭管理员使用的静态界面。

### 方案 B：生产应用中的管理员页面

可复用现有 UI 与认证，但会让真实儿童评测数据进入生产攻击面、数据库和备份语义，迫使项目增加权限、迁移与导入导出改动。与“样本留在仓库外私有目录”的目标冲突，因此不采用。

### 方案 C：继续手写 JSON 与坐标

改动最小，现有工具已经支持；但区域框、重复题号和多维元数据容易出错，不适合持续积累 60 道以上样本。保留为高级用户入口，不作为推荐工作流。

## 用户流程

1. 使用者在仓库外创建私有目录，并把已脱敏的照片放入 `photos/`。
2. 运行 `npm run eval:label -- --dataset /绝对/私有目录`。
3. 工具检查目录在仓库外，发现支持的图片，固定监听 `127.0.0.1` 的空闲端口并输出带随机会话令牌的本地 URL。
4. 浏览器左侧显示照片与已有区域框，右侧编辑页面元数据、候选题和期望答案；拖拽创建区域，选择后可删除或重画。
5. 每次有效编辑写入 `.exam-answer-labeler.json` 草稿；写入采用临时文件加原子替换，文件权限为 `0600`。
6. 页面显示完成度与错误。只有全部样本满足正式 manifest 契约时，“导出评测清单”才可生成或替换 `manifest.json`；替换前在同目录保留一个上一版本备份。
7. 使用者按现有文档显式设置评测 Provider 环境变量，运行评测 CLI 并把报告写回私有目录。

## 数据契约

正式 manifest 保持 `samples` 顶层结构，并向后兼容现有文件。标注器生成的样本增加：

- `grade`：整数 1～6。
- `subject`：`数学`、`语文`、`英语`。
- `handwriting`：`清晰`、`潦草`、`涂改`、`混合`。
- `photoQuality`：`清晰`、`阴影`、`倾斜`、`模糊`、`混合`。
- `expected[].questionType`：复用 `src/lib/question/question-type.ts` 的标准题型 key（`single_choice`、`multiple_choice`、`true_false`、`fill_blank`、`calculation`、`solution`、`reading`、`cloze`、`writing`、`other`）。

旧 manifest 缺少这些字段时仍可运行评测，但报告把缺失值归入“未标注”，且不能据此宣称完成分层验收。标注器导出时要求这些字段完整。

草稿文件使用独立 `version: 1`、整数 `revision` 和宽松样本结构，允许未完成字段；正式 manifest 不包含草稿 revision、界面状态或绝对路径。图片路径始终相对数据集目录。

## 架构

### 共享 manifest 契约

把现有评测脚本中与 Provider 无关的 manifest 解析、路径边界和元数据归一化提取到 `scripts/exam-evaluation/manifest.mjs`。评测 CLI 与标注器导出共同调用同一个严格校验入口，避免两套规则漂移。标注器另有草稿校验与正式导出转换函数。

### 本地服务

`scripts/exam-evaluation-labeler.mjs` 解析唯一必需参数 `--dataset`，要求已存在的绝对目录且其真实路径位于仓库外。服务端只使用 Node.js 内置模块：

- `GET /api/state`：校验会话令牌后返回草稿、图片清单、revision 和完成度，不返回绝对路径。
- `GET /api/image/:id`：校验会话令牌后按启动时生成的不透明 ID 提供白名单图片，拒绝任意路径与符号链接逃逸。
- `PUT /api/draft`：要求同源、会话令牌、JSON Content-Type、请求体上限和匹配 revision；原子保存后 revision 加一。
- `POST /api/export`：在相同保护下严格校验并生成 manifest；已有文件先原子保存为单一上一版本备份。

所有 API 错误只返回固定类别和字段位置，不回显答案、绝对路径或原始异常。服务固定绑定 `127.0.0.1`，不提供修改 host 的参数；端口可选，默认由系统分配。随机令牌位于启动 URL 的 fragment 中，前端读出后只通过自定义请求头发送；服务端同时严格校验 `Host` 与写请求 `Origin`，防止 DNS rebinding 和跨站请求。

### 浏览器界面

静态 HTML/CSS/JavaScript 由本地服务提供，不引入前端构建步骤。界面采用移动端可读、桌面端双栏布局；照片标注主要面向 MacBook 桌面浏览器。区域框基于图片实际显示矩形计算 0～1 坐标，缩放和窗口变化不改变已保存坐标。键盘操作至少支持上一页、下一页、保存以及删除当前框；所有输入都有可见标签和错误提示。

### 分层报告

报告版本由 2 升为 3，仍保留全局指标与逐题布尔结论，并增加 `breakdowns`：按固定维度和值输出 `expectedCount`、`matchedCount`、`exactAnswerCount`、两项准确率。逐题结果只增加枚举化分层标签，不包含答案、题干、框坐标或照片路径。v2 与 v3 的全局指标口径相同，新增分层字段不用于反推旧报告。

原始报告继续包含人工 `paperId` 与 `questionId`，因此“脱敏”只表示不复制照片、答案、路径、题干和凭据；原始报告仍是私有数据，必须留在仓库外。公开交付只摘录样本组成和汇总指标。

## 安全与隐私

- 数据集真实路径必须在当前源码根、Git common dir、主 checkout 和 Git 已注册的其他工作树之外，且图片 realpath 必须仍位于数据集内。
- 只发现普通 JPEG、PNG、WebP，单图不超过 20 MiB，最多 1000 页；限制遍历深度与总目录项，使用 `lstat` 忽略隐藏目录和所有符号链接。草稿只保存稳定相对路径，不保存进程内图片 ID。
- 所有 API 均校验随机令牌；写请求额外校验同源 `Origin`、方法、JSON Content-Type 和请求体大小。响应设置严格 CSP、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`，不设置 CORS；界面用 `textContent` 和 DOM 属性呈现私有文本，不拼接不可信 HTML。
- 草稿、manifest 与备份权限为 `0600`，采用同目录临时文件原子替换；更新 manifest 时先原子写成上一版本备份，再原子替换正式文件，避免崩溃后正式文件缺失。进程退出时清理自己的临时文件。
- 控制台不打印图片名、题目、答案、绝对数据集路径或请求正文；只打印本地 URL、计数和通用错误。
- 不自动打开浏览器，不读取 `.env`，不调用 Provider，不写 SQLite。

## 错误处理

- 参数、目录、图片或现有草稿无效时启动失败，退出码为 2，并给出不含私有内容的操作提示。
- revision 冲突返回 409，界面要求重新加载，绝不静默覆盖另一标签页的编辑；测试覆盖两个客户端同时基于同一 revision 保存。
- 未完成草稿可以保存；导出失败时保留原 manifest，不生成部分文件。
- 新增照片在重新扫描后合并为未完成样本；已移除照片保留草稿但标为缺失，必须恢复或显式删除后才能导出。
- 服务收到 SIGINT/SIGTERM 时停止接受请求并正常关闭。

## 测试与验收

- 单元测试覆盖参数解析、仓库外边界、符号链接逃逸、图片发现、草稿恢复、revision 冲突、严格导出和原子写入。
- HTTP 集成测试使用系统临时目录和合成图片，覆盖令牌/Origin/Content-Type/体积限制、图片白名单、保存与导出；测试后删除临时数据。
- DOM 单元测试覆盖归一化框坐标、缩放稳定性、1～4 框限制、页面导航和完成度提示。
- 现有评测 CLI 的退出码、错误脱敏、输出不覆盖、图片限制和“首次模型调用前完成全部输入校验”行为继续通过；新增旧 manifest 兼容、报告 v3 与分层报告断言。
- 完整 `npm run lint`、`npm run test:unit`、`npm run test:integration` 通过；真实照片与真实 Provider 不进入自动化。
