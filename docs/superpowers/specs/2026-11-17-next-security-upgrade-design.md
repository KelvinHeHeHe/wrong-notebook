# Next.js 安全升级设计

> 状态：已批准
> 日期：2026-11-17
> 触发原因：任务 06 最终构建时，Next.js 16.4.3 显示已知安全漏洞提示，并建议运行官方 security 升级器。

## 意图

在独立工作树中使用 Next.js 官方升级器选择安全修复版本，消除正式发布阻断项，同时把依赖变化、兼容性影响和验证证据限制在可审查范围内。

## 方案

采用官方命令 `next upgrade --agent=security --internal-nudge-id=b89e47d1-931b-4167-a388-635b3c20f5bb`。相比手工猜测补丁版本，它能按实际公告选择修复版本；相比直接修改 `main`，独立工作树允许完整检查和回退。

## 范围

- 允许修改安全升级器认定必须变化的 Next.js、React 及直接配套依赖与锁文件。
- 只有官方 codemod 明确要求时才接受源代码或配置调整，并逐项审查。
- 更新任务 06 验收文档，记录升级版本、验证结果和剩余风险。
- 使用官方 npm registry，锁文件不得出现 `npmmirror`。

## 非目标

- 不借机升级无关依赖、重构业务代码或改变用户行为。
- 不修改 Prisma Schema、正式迁移、备份版本或用户数据。
- 不自动合并、推送、打标签、发布包或镜像。

## 验收标准

1. 官方 security 升级器成功完成，依赖差异可解释且只与安全修复直接相关。
2. `npm ls next react react-dom` 无依赖错误，生产构建不再被同一安全提示中止。
3. 完整 `scripts/ci.sh` 与 96 个 Playwright 用例通过。
4. 公开历史、锁文件 registry、业务 Schema/迁移/备份实现检查通过。
5. `docs/MVP_ACCEPTANCE.md` 与 `docs/MVP_PLAN.md` 不再把已完成的本地安全升级写成未处理，但仍明确远端 CI、真实样本和生产签名尚待完成。
